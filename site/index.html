A cache with a boundary

Reuse follows the inputs.

A cache hit is valid only when the effective compile inputs match. If Mitts cannot account for an input, that action stays on the uncached path.

Input record

Know what changed

Action keys include tracked source, dependency, toolchain, target, feature, flag, configuration, and environment inputs.

Shared store

Keep objects immutable

Content-addressed artifacts are verified before use. Compatible outputs can be reused across builds and workspaces.

Workspace state

Restore into a boundary

Mutable build outputs stay in the workspace target directory, separate from the shared artifact objects.

Current cache policy

Eligible work is a deliberate subset.

Mitts starts with actions whose inputs it can track. Unsupported or unknown cases remain visible and uncached.

Eligible when tracked

Pure Rust compile actions

The initial cache scope covers Rust library and binary actions with verified input identities.

  • Library and binary outputs with matching action keys
  • Corrupt objects are rejected and rebuilt
  • Concurrent work coordinates through single-flight locks
  • Build scripts, procedural macros, and mixed native library outputs bypass the initial cache
