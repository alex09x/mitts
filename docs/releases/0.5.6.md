# Mitts 0.5.6

- One `-j` budget for the units of a build and the jobs they start, as under Cargo. Units
  were bounded by `-j` slot locks and the jobs they start (rustc's codegen threads, and
  make, ninja or cc-rs in build scripts through `CARGO_MAKEFLAGS`) by a separate pool of
  `-j` tokens, so a build could run about twice `-j` jobs at once. Now the pool holds
  `-j - 1` tokens, like Cargo's pipe: the first unit of a Mitts process runs on its
  implicit token and every other running unit holds one pool token. The pool is shared by
  Mitts processes on the machine; a token held by a process that was killed comes back
  with the next holder of its slot. The tests for this are Unix only (Windows already took
  units and nested jobs from one per-process semaphore).

No new performance benchmark result is claimed by this release.
