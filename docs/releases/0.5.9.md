# Mitts 0.5.9

- `[env]` of the project's `.cargo/config.toml` reaches the build scripts of its
  dependencies, as under Cargo. It was read from the configs above each package's own
  directory, and a registry dependency lives in the shared source store, so its build
  script never saw the project's `[env]`: `[env] LIBSQLITE3_FLAGS` did not reach
  libsqlite3-sys, cold builds included. A variable a build script watches with
  `rerun-if-env-changed` is now read with `[env]` too, so a changed value runs the script
  again.
- A compile error of a workspace member shows its file, line and source snippet in the
  human output (#195). The report looked the file up from the package directory while
  rustc names it from the workspace root, and printed only the message. An error whose
  source cannot be read still shows `path:line:col`.
- `--timings`, `--slow-units`, `--ignore-rust-version` and `--future-incompat-report`
  are options of the commands that compile, as in Cargo, not global options: `mitts fmt`,
  `mitts gc` or `mitts login` no longer list them. `update`, `generate-lockfile` and
  `add` take `--ignore-rust-version`. Written before the command (`mitts --timings
  build`), they are now rejected, as by Cargo.

No new performance benchmark result is claimed by this release.
