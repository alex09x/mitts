# Mitts 0.5.8

- Your own crates are no longer stored in the shared cache. Workspace members and path
  dependencies change with every edit, and Mitts stored each version of them, tests and
  binaries included, in `~/.cache/mitts`. A project with 96 integration tests built in a
  fresh worktree per change put 70 GB of its own test executables there within two
  hours. Their outputs, build-script results and cache entries now go to
  `target/<profile>/.mitts-store`, which keeps the last version of each unit for each
  command (`build`, `test`, `check`, `clippy`): a build with nothing changed restores
  them, an edit replaces them (the target does not grow with edits), and `mitts clean`
  or `rm -rf target` removes them. The shared cache holds
  registry and git dependencies. `MITTS_SHARE_WORKSPACE_CRATES=1` stores your own crates
  there as before, so a second worktree of the same commit reuses them.
- The cache size limit holds while builds run. A build holding the cache kept every
  object used in the last two hours, so builds without pause kept the cache far over
  `MITTS_CACHE_MAX_BYTES`. When the limit cannot be met that way, objects older than ten
  minutes that no workspace links to are pruned too.
- On Windows (MSVC) a library of a package with a build script no longer keeps the build
  script's `build_script_build.pdb` among its cached outputs.
- `mitts fetch` fits in the open-file limit of a macOS terminal (256), as Cargo. Fetching
  hundreds of crates failed with "Too many open files": every downloaded crate waiting to
  be unpacked held its lock file open, on top of 64 download connections. Downloads and
  unpacks now run as many at once as the process's open-file limit allows.

Checked before the release: the full test suite on Linux, macOS and Windows CI; the OS
matrix with the full suite on eight x86_64 Linux distributions and seven native aarch64
ones, and a test subset on arm64 and riscv64 under emulation. On each one the project's own
crates stay out of the shared cache.

No new performance benchmark result is claimed by this release. The published benchmarks
were measured when Mitts stored the projects' own crates in the shared cache; that now
takes `MITTS_SHARE_WORKSPACE_CRATES=1`.
