# Mitts 0.5.5

- Build scripts get the build's job pool as Cargo gives it: descriptors the script
  inherits (`-j --jobserver-fds=N,N --jobserver-auth=N,N` in `CARGO_MAKEFLAGS`). Mitts
  named the pool as `fifo:<path>`, a form only GNU make 4.4 and later read; make 4.3
  (Ubuntu 24.04, Debian 12) stopped with "invalid --jobserver-auth string", so `-sys`
  crates built through cmake and make (libz-ng-sys, used by starship) failed under Mitts
  and built under Cargo.
- The real-projects check now runs on Linux and macOS as well as Windows: twelve projects
  (ripgrep, fd, bat, starship, clap, difftastic, bottom, just, hyperfine, alacritty,
  soulseek-rs, tokio) go through Mitts and through Cargo on ubuntu-24.04, macos-15 and
  windows-2022 for every change. It compares the build outputs, the binary's `--version`
  where the project has one (not clap and tokio), the test results (the test step is
  skipped for alacritty and tokio), and checks that an unchanged rebuild compiles nothing
  and that a deleted target directory comes back from the cache. Cargo runs there only as
  the reference. The jobserver fix above is what its first Linux run found.

No new performance benchmark result is claimed by this release.
