# Mitts 0.5.4

Mitts is now checked against Cargo itself: the same projects go through both, and what a
user sees must agree. Cargo runs there only as the reference.

- Differential tests with Cargo as the reference: the lockfile, `metadata` (packages and
  the resolve graph), five `tree` forms, `pkgid`, `locate-project`, the files a build
  leaves, `run` output, test results, `new`/`init`, `add`/`remove` and `package --list`
  match Cargo's. Fixed on the way:
  - `Cargo.lock`: Cargo's header, no trailing blank line, version 4 for new lockfiles
    (3 when a member's `rust-version` predates 1.78); an existing lockfile keeps its
    version.
  - `add --path` writes the package's version beside the path; `remove` drops a
    dependency table it empties.
  - `tree -e features` shows the `default` feature node.
  - `metadata`: Cargo's package ID spec (`path+file:///C:/…` on Windows), members in
    declaration order, fields inherited from `[workspace.package]`, the build script as
    a `custom-build` target, the resolve graph of every platform.
- Twelve real projects are built, run and tested on Windows (x86-64 MSVC) by every change,
  against Cargo: ripgrep, fd, bat, starship, alacritty, bottom, difftastic, hyperfine,
  just, clap, tokio and soulseek-rs. Fixed on the way, on every platform unless noted:
  - `cargo:rustc-link-arg-bin=<bin>=<arg>` and the other scoped link arguments reach
    only their targets (ripgrep's `/MANIFEST:EMBED`).
  - `rustc-link-lib` goes to the package's library only, as in Cargo; the binary links it
    through the rlib (starship's version resource was linked twice on Windows).
  - Build scripts link with their build dependencies' `rustc-link-search` directories and
    find a build dependency's own dependencies (hyperfine, bat, starship, bottom,
    alacritty on Windows).
  - Build-script paths into `OUT_DIR` follow it when it moves, also when the script's
    result comes from the cache (alacritty).
  - Build scripts run with `RUSTUP_TOOLCHAIN`, as under Cargo started through rustup, and
    with `PATH` joined by the platform's separator (Windows).
  - `CARGO_BIN_NAME` is set for a binary's unit tests (difftastic).
  - `-p name` matching two versions is refused as in Cargo; `-p name@version` selects
    one (tokio's workspace).
  - Only the requested packages' libraries are copied to `target/<profile>`.
  - On Windows an unchanged rebuild after `mitts test` reuses the integration tests
    (dep-info `env-dep` values were read with their escaping).
  - A linker failure shows rustc's notes, which name the missing file.
- Windows installers tested on GitHub's Windows runners: PowerShell 7 and Windows
  PowerShell 5.1, cmd.exe, Git Bash, MSYS2 (MSYS, MINGW64, UCRT64, CLANG64), Cygwin, the
  setup action and Windows on ARM64. `install.ps1` no longer leaves variables or strict
  mode in the caller's session, enables TLS 1.2 on Windows PowerShell 5.1, upgrades a
  `mitts.exe` that is running a build, and builds from source on ARM64 when Cargo is
  installed; `install.sh` does the same running-binary upgrade and recognises every MSYS2
  environment.
- The VS Code extension is tested on Linux, macOS and Windows; its Install command uses
  the PowerShell installer on Windows.

The build-script cache protocol is v11: results recorded before it are not reused.

No new performance benchmark result is claimed by this release.
